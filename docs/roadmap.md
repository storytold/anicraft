# AniCraft roadmap

The planned milestones (M0 to M8) are done. From here the roadmap is a **guideline, not a
timeline** ([ADR 0125](adr/0125-the-roadmap-as-a-guideline.md)): a prioritised backlog that says what we would pick next and why, and
where every open pull request and feature request fits. Nothing here has a date.

The goal is **full feature parity with the reference app**, Adobe Animate, on a base that
doesn't break. [`parity.md`](parity.md) is the feature-by-feature matrix; this page orders its
gaps. In short: bugs and reliability first, then the parity gaps artists meet most often, then
the long tail.

## How the backlog is ordered

Items are compared on six things, in this order. An earlier one wins over a later one.

1. **Priority.** Who is stopped, and how many. A crash, a hang, lost work or an app that won't
   start comes before any feature. Among features, the ones artists use every day come first.
2. **Correctness.** Something that does the wrong thing comes before something missing: wrong
   output is trusted until it bites.
3. **Completeness.** Finishing a feature that is partly there comes before starting a new one.
4. **Reliability.** Work that makes a result the same on every machine and every run (GPU
   fallbacks, platform input, verified installs) comes before work that only adds.
5. **Robustness.** Bounds on hostile or huge input, and tests that would catch a regression.
6. **Independence.** Of two items otherwise equal, the one that can merge without waiting for
   another comes first, so that several can be in review at once.

Every pull request, ours as much as anyone's, gets a principal-engineer review before it
merges: is this how a principal engineer and a senior designer would have done it? The
questions are in [ADR 0125](adr/0125-the-roadmap-as-a-guideline.md).

**Reading the table.** *Size*: **S** is one small PR, **M** is one slice of the kind the
milestones shipped (model, commands, rendering, shell, tests, docs), **L** is several slices and
an ADR. *Lane* names the part of the code an item mostly touches. Two items in **different
lanes** with no entry under *Needs* can be built and merged in parallel; two in the **same
lane** are better done one after the other, because they meet in the same files. The ids are
stable: an item keeps its id when the order changes, a new item takes the next free number
wherever it is placed (P-056 was in the first tier), and a finished item leaves the table for
the changelog.

## Open pull requests from outside, each with its slot

Every open pull request that is not ours has a backlog id and a state, so its fate is never in
doubt. This table is brought up to date whenever one opens, closes or changes state (list them
with `gh pr list --state open`). The states:

* **planned**: we want it. It merges when its item is reached in the backlog, or sooner if it is
  ready and touches nothing in flight, once it has what the table says it still needs.
* **superseded by**: the same result has landed another way. The PR can close, with thanks, and
  anything in it that `main` still lacks is named.
* **declined**: we won't take it, and why.
* **held**: we can't decide yet, and what we are waiting for.

What `main` does today, dimension by dimension, with what is not there yet. A PR that changes
a dimension updates its row, as before; the rows are long because they are complete. For the
same facts feature by feature, see [`parity.md`](parity.md).

Streaming WAV headers and PCM sample blocks now delegate to `craft_audio::wav_stream`;
AniCraft retains mixing, frame-range limits, temporary-file cleanup and VFS writes.
This integration depends on craft-libs #1962 and still requires hosted parity validation.

The experimental [Array panel](array-panel-design.md) previews Linear, Grid, and Radial arrays of
one symbol instance, with a neutral track for Transform and Colour Effect stops. Array mode stays active
when its dock tab is hidden or closed. Spatial Array commits the preview in one undo step and
resets the next Array to defaults at its source symbol. Linear Arrays can also commit one
Symbol instance to native Classic Tween or Hold Keyframes, beginning at the playhead.
Circle Arrays can commit one native Motion Tween with an editable Bézier path, eased path timing, and animated property stops.
Spiral Arrays can commit one editable Motion Tween with multiple signed turns and eased angular timing.
Arbitrary Path conversion remains planned. Cancel, Escape and None retain the unfinished
configuration while the original instance stays selected. Spatial Array can give each
instance its own Symbol definition and timeline in the same undo step. The selected-stop card has draggable
scales and multi-turn rotation in Transform, and Alpha, Brightness, Tint and Advanced channels
in Colour Effect. The default stops start with the source instance's values. An inserted stop
copies the prior stop's entire snapshot, including its outbound ease.
Radial Arrays offer Circle and Spiral buttons. Grid Arrays have a rectangular gizmo, linked or
independent row and column counts and spacing, and optional artwork mirroring when an axis
reverses. Grid Property Distribution samples stops across columns, down rows, or in row-major
order. Stagger supports independent signed row and column offsets with repeating or accumulating placement. Filter cards start collapsed in each Array session.
Filter stops support all seven families, including signed Adjust Color values. Both gradient filters
interpolate corresponding ramp positions with a fixed source stop count, order, and transparent pin.
Quality, Type, and switches hold at the authored stops. Copies preserve the source filter stack and
on/off states.
An active Array session has its own undo and redo for geometry and stop edits, coalesced by gesture.
The Easing section offers global and independent outbound presets for distribution, transform,
colour and continuous filter parameters. Quit resolves an active Array before asking about unsaved documents.
Linear arrays have draggable Start and End circles and a movable connecting line. Coordinates,
direction, length and spacing are editable in the panel. All modes display white instance markers with
the handles toggle on. Dim Stage foregrounds the preview over dimmed artwork. Geometry-only
Linear edits reuse the instances and eligible stage tiles. Auto can reposition warmed Blur images
during eligible Linear stage drags, then draws exact tiles when the pointer pauses or is released.
Radial distribution supports an explicit
Closed Loop and open arcs with a signed sweep, spiral offset and two-axis centre drift. Its stage
controller has Centre, Start, End and Drift handles, a draggable drift bar and a curved guide.

**Future session recovery.** A graphics-backend restart recovers unsaved document edits, but an
active Array draft and its session Undo/Redo history are lost. Restore the draft and both history
branches with the original source in the recovered document. See [Array graphics recovery](array-panel-design.md#graphics-backend-restart).

## Risks

| Risk | Mitigation |
|---|---|
| GPU and CPU renderers drift apart | Golden parity tests in CI; CPU stays the oracle. |
| XFL edge encoding is under-documented | Build a self-authored corpus; unknown elements kept verbatim; fail with readable errors. |
| egui immediate-mode cost with big timelines | Virtualise the frame grid (paint only visible cells); cache layer row summaries per revision. |
| Snapshot undo memory | `Arc` structural sharing ([ADR 0001](adr/0001-undo-persistent-snapshots.md)); history size cap with a preference. |
| Parity pulls in knowledge of the reference app that isn't clean | `parity.md` is written from public documentation in our own words; format work uses public descriptions and the fixtures `standards/clean-room.md` allows (files we generate, published files pinned by URL and sha256, files their maker licenses); a PR whose provenance is unclear is held until it is answered, as the binary `.fla` importer was ([ADR 0120](adr/0120-legacy-fla-compound-binary-import.md)). |
| The backlog and the open pull requests drift apart | The outside PR table is updated whenever a PR opens, closes or changes state, and a PR without a row is given one before it is reviewed ([ADR 0125](adr/0125-the-roadmap-as-a-guideline.md)). |
| Parity status goes stale | A PR that changes a feature's status changes its row in `parity.md` in the same PR; rows marked † or ? are checked first. |
